# Working on Turbofan

Turbofan: a Raft-replicated state machine framework in Rust, and an OMS built on it.
The house style is [docs/STYLE.md](docs/STYLE.md) (Tiger Style, adapted from Turbojet's): read it
before writing code.

- `crates/turbofan-cluster` is the reusable core. It must never depend on a service or mention
  what one does: service payloads are opaque bytes. `raft/` replicates opaque records and knows nothing of
  sessions or services; `node/` layers those on top.
- The core is sans-IO: inputs in, outputs out, no IO, no clock reads. The driver and the
  simulator do the IO.
- The wire protocol is `crates/turbofan-cluster/schema/cluster.xml`, generated by `build.rs` with
  `crates/turbofan-sbe` (SBE codegen and runtime, copied from Turbojet). Change the schema, not the
  generated code, and only as `crates/turbofan-cluster/docs/WIRE.md` allows: old and new nodes run side
  by side. A generator change: `SBE_REGENERATE=1 cargo test -p turbofan-sbe` rewrites its
  checked-in test codecs.
- Services live in repositories of their own, depending on it by git: the OMS (an order book) is
  at `../oms`. A framework change can break one: check it there with `cargo update -p
  turbofan-cluster` and its `scripts/check.sh`.
- `scripts/check.sh` (fmt, clippy `-D warnings`, tests, rustdoc, `cargo deny`) before calling work
  done.
  `cargo bench -p turbofan-cluster --bench cluster` for throughput and latency (`--features tls`
  adds runs over TLS) (CI's summary has
  each run's).
  `SIM_SEEDS=1000 cargo test -p turbofan-cluster --release --test sim` for a longer simulation; a failure
  prints `SIM_SEED=<n>`, which replays it.
- `scripts/fuzz.sh` fuzzes what the cluster reads from the network (`crates/turbofan-cluster/fuzz`,
  outside the workspace; nightly and cargo-fuzz). `check.sh` only checks it builds.
