# Working on Turbofan

Turbofan: a Raft-replicated state machine framework in Rust, after Aeron Cluster, and an OMS built on it.
The house style is Turbojet's [STYLE.md](../turbojet/docs/STYLE.md) (Tiger Style): read it before
writing code.

- `crates/turbofan-cluster` is the reusable core. It must never depend on `crates/oms` or mention orders:
  service payloads are opaque bytes. `raft.rs` replicates opaque records and knows nothing of
  sessions or services; `node.rs` layers those on top.
- The core is sans-IO: inputs in, outputs out, no IO, no clock reads. The driver and the
  simulator do the IO.
- The wire protocol is `crates/turbofan-cluster/schema/cluster.xml`, generated by `build.rs` with
  `turbojet-codegen`. Change the schema, not the generated code.
- `crates/oms` is one service on it: the order book (`src/lib.rs`), its schema
  (`schema/oms.xml`), the `oms-node` binary, and `examples/gateway.rs` (a gateway and a venue
  that check every order's reports; `tests/failover.rs` runs it while killing nodes).
- `scripts/check.sh` (fmt, clippy `-D warnings`, tests, rustdoc) before calling work done.
  `SIM_SEEDS=1000 cargo test -p turbofan-cluster --release --test sim` for a longer simulation; a failure
  prints `SIM_SEED=<n>`, which replays it.
- `scripts/fuzz.sh` fuzzes what the cluster reads from the network (`crates/turbofan-cluster/fuzz`,
  outside the workspace; nightly and cargo-fuzz). `check.sh` only checks it builds.
